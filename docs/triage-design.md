# 离线告警研判设计

## 输入契约

输入是 UTF-8 Wazuh 告警 JSONL，允许 BOM 与空行。必须有带时区的顶层 `timestamp`、非空 `manager.name` / `agent.id`、数值规则 ID 和整数等级 0-15。`data.srcip` 若存在，须为有效 IP；规则组和 ATT&CK ID 须为字符串列表。

解析失败默认中止，不输出成功报告。`--skip-invalid` 是显式的部分处理模式，报告记录被拒绝行的位置与错误。导出来源必须可信，研判程序不验证告警真实性。

## 稳定标识与重复

Wazuh 原生 ID 按 manager + agent 命名空间哈希；缺少原生 ID 时，按时间、规则、等级、来源、用户、URL、组及映射等标准化字段生成语义标识。标识不是原始行内容哈希。

相同标识且标准化内容一致的记录只计一次，所有不同证据行号仍保留。相同原生身份出现不同内容则中止，避免悄悄丢掉冲突。

无原生 ID 时，同一时间、相同标准化字段的独立事件可能被视为重复。需要精确计数时应保留 Wazuh 原生 ID，不应依赖去掉原始载荷后的语义标识。

## 限时降噪

策略文档版本为 1；每项必须明确以下字段：

| 字段 | 约束 |
| --- | --- |
| `id` | 非空且唯一 |
| `rule_ids` | 非空数值 ID 列表 |
| `manager_names` / `agent_ids` | 明确对象，禁止 `*` |
| `source_cidrs` | 明确网段，禁止 IPv4 / IPv6 `/0` |
| `starts_at` / `expires_at` | 带时区，开始小于到期，最长 30 天 |
| `owner` / `reason` / `ticket` | 非空审计元数据 |

策略状态为 `pending`、`active`、`expired`。仅当当前评估时钟在 `[starts_at, expires_at)`，且告警时间也在该区间，所有范围条件同时满足时，才从本地待审队列移出。

过期策略不会因为处理的是旧告警而继续生效。`--now` 只用于受控历史重放；演示使用固定时钟，实际评估默认使用当前 UTC 时间。它不是审批验证或防篡改机制，不能把演示配置当成生产白名单。

降噪不删除事件或证据，不修改源日志，不写回 Wazuh，不触发封禁。JSON 同时保存标准化事件、匹配策略 ID 和每项策略状态/命中数。

## 事件归并

归并键为：

```text
manager.name + agent.id + actor + category
```

actor 优先使用规范化 IP；无 IP 时使用已提供的用户，无 IP 且无用户时逐事件隔离。类别根据显式规则组选择，未知类别退回具体规则 ID，避免把所有未知事件混为一种攻击。

事件按 UTC 时间和稳定 ID 排序。在同一键下，从首条事件开始使用默认 300 秒的锚定窗口，达到右边界则新建事件；不因每次新事件无限延长原窗口。不同主机、manager、来源、类别互不合并。

晚到的更早证据会改变窗口或事件 ID，这不是跨批次持久工单系统。当前实现不保存历史状态、不做跨技术攻击链推理，也不把没有身份的事件默认视为同一攻击者。

## 输出与优先级

`incidents.json` 保存摘要、事件、降噪审计、输入错误及限制说明；`triage.md` 提供队列、归并理由、ATT&CK 标签和原文件行号。

优先级由最高 Wazuh 等级生成，不根据猜测的攻击成功率升权。输入顺序变化不影响固定时钟下的标准化报告。合并只降低待审项数量，不改变规则等级或原始事件数量。

所有 Markdown 中的外部文本需转义，避免日志字段成为 HTML 或链接。输出不带 `full_log`，但 URL 和用户名仍可能包含敏感信息，须按安全数据保管。

## 已知边界

- 读取完整输入后批处理，无实时消费、持久存储或吞吐承诺。
- 不执行原生检测规则，不验证漏洞可利用性。
- 文件名 + 行号是位置引用，不是不可篡改证据；应另行保存受控原文件。
- ATT&CK 标签及规则等级只是研判辅助，无告警不代表没有攻击。
- 该项目没有自动响应、网络扫描或 LLM 调用，避免将确定性流程包装成未实现的 AI 能力。
